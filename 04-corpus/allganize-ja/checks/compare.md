# PDF変換比較手順書 点検結果

適用Skill: logic-jp-check

## 論理

- 〔型A〕速度だけで上位を選ぶと、RAG回答に必要な記述の欠落を見逃す → 精度条件を先に満たし、速度を順位決定に使う基準へ修正した。
- 〔型D〕総合平均だけでは文字埋込みPDFとスキャンPDFの用途差が隠れる → 用途別に上位製品を選べると明記した。
- 〔型C〕キーワード一致は別ページの偶然一致や図の意味理解を過大評価する → target_page_noの照合、LLM三値判定、食い違いの目視を追加した。
- 〔型E〕出力文字数が多いことを高精度の原因・根拠にはできない → 重複、ヘッダー、幻覚を独立に確認する観点を追加した。
- 〔型C〕ピークRAMの説明が旧実装の `ru_maxrss` 差分を指していた → 実装どおり、対象PID群のRSSとVRAMを0.5秒間隔で観測する近似値へ修正した。
- 〔型D〕公開VLMと非公開VLMの結果を同じ行へ集約するとモデル条件が重なる → `docling-vlm-commercial` を独立行として追加した。
- 〔型B〕商用VLMの常駐モデル込みリソースと、他プロダクトの変換プロセスだけの値を直接比較すると前提が揃わない → 測定範囲の差を明記し、絶対値を直接比較しない判断基準を追加した。

## 日本語

- 〔指摘〕〔明快〕LLM判定の「正しい」が判定者により揺れる → sufficient / partial / missing の条件を定義した。
- 〔指摘〕〔具体〕「表が保たれる」の基準が曖昧だった → 0〜2点の採点基準と確認項目を定義した。
