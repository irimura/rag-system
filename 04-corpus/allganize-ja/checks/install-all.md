# PDF変換プロダクト一括インストール手順書 点検結果

## 日本語

- 〔指摘〕〔明快〕「一括」が一つの無停止コマンドを意味するように読めた → 一つの手順書に集約し、ライセンス・互換性・CUDAの確認点で区切って順番に実行する意味だと定義した。
- 〔指摘〕〔具体〕venvを分けるだけでは共有状態が不明だった → OS、ドライバー、GPU、RAM、モデルキャッシュ、環境変数は共有されると明記した。
- 〔指摘〕〔用語統一〕venvの切り替え方法が個別手順書のactivate方式と混在する → 一括手順ではvenv内のPythonとCLIを直接指定する方式へ統一した。
- 〔指摘〕〔具体〕activate済みvenvの `python3` で新しいvenvを作るおそれがあった → activateを解除し、`${base_python}` の絶対パスを固定してから全venvを作る手順へ修正した。
- 〔指摘〕〔明快〕pip導入に失敗しても後続確認へ進めた → 各製品を `set -e` のサブシェルで実行し、CLI確認・版記録・完了マーカーまで成功した場合だけ完了とするよう修正した。
- 〔指摘〕〔具体〕導入版を標準出力にしか残していなかった → `metrics/<product>-versions.txt` へ保存し、再実行前後の差分確認を追加した。
- 〔指摘〕〔具体〕再実行失敗後も以前の完了マーカーが残った → 各製品の再実行開始時に完了マーカーを削除し、全確認の成功後だけ作り直すよう修正した。
- 〔指摘〕〔明快〕CUDA確認が `False` でも終了コード0だった → GPUを既定とする5製品はCUDAを使えない場合に終了コード1とし、完了扱いにしないよう修正した。
- 〔指摘〕〔具体〕AnyDocのpip版にCLIが含まれるか未確認だった → CLIを要件から外し、`anydoc.to_markdown()` が呼べることをインストール完了条件にした。
- 〔指摘〕〔具体〕MinerUのOCR処理とAES暗号化PDFのページ数取得に必要な依存が不足していた → `six==1.17.0` と `cryptography==49.0.0` をMinerUの導入要件へ追加した。
