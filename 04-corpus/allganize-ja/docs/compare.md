# PDF変換比較手順書

## 1. 比較の前提

全プロダクトを同じNode Aで順番に実行する。GPUを共有する別プロセスを止め、各プロダクトのバージョン、モデル名、Gitコミットまたはパッケージ版を結果へ記録する。サンプル比較と全件実行を混ぜない。

速度は同じノードで直接比較できる。ただし、初回モデル取得時間は変換時間から除き、ウォームアップの有無を揃える。AnyDocのスキャン失敗など、仕様上の適用範囲外も成功率には含め、用途別の注記を添える。

## 2. 第1段階: サンプル比較

```bash
cd 04-corpus/allganize-ja
python3 scripts/select_sample.py
column -s, -t sample_list.csv
```

特定domainの全件を比較する場合は、次のように完全一致するdomain名を指定する。この場合、`--size` は使用しない。

```bash
python3 scripts/select_sample.py --domain IT
column -s, -t sample_list.csv
```

`document_type_guess` はメタデータに基づく推定値である。全行について `pdffonts` でフォント有無を確認し、1ページ目も表示して「文字埋込み」または「スキャン」に直す。「未判定」を残さない。約10件でdomain、文書タイプ、評価type（段落・表・画像）が不足した場合は、候補を手動で入れ替え、理由をCSV末尾の別管理メモではなく比較結果へ記録する。

各[変換手順書](convert/)に従って、`--all` を付けずに実行する。変換済みのMarkdownは既定でスキップされる。失敗だけを再試行するときは原因を直して `--force` を付ける。

## 3. メトリクス集約

```bash
python3 scripts/aggregate_metrics.py
sed -n '1,80p' results/comparison.md
```

CSVの共通列は、ファイル名、ページ数、所要秒、ページ/秒、出力文字数、成否、エラー、ピークメモリ、GPU使用有無、VRAM使用量である。ピークRAMは変換プロセスとその子孫のRSS合計、VRAMは同じPID群の使用量を、それぞれ `psutil` と `nvidia-smi` で0.5秒間隔に観測した近似値である。他プロセスの使用量は含めない。短いピークを取り逃すことがあるため、絶対的な容量保証には使わない。失敗行のページ/秒は空欄とする。

速度は成功文書の「秒/ページ」の中央値を主指標とし、P90も表外に記録する。成功率は空でないMarkdownを生成できた文書数を分子、対象サンプル数を分母にする。

## 4. 精度検証

### 4.1 評価対象の対応付け

`rag_evaluation_result.csv` を `target_file_name` で出力Markdownへ対応付ける。`target_page_no` は1始まりとして扱い、原本PDFの該当ページと正解回答を開く。Markdownにページ境界がない製品では、該当記述の全文書検索も併用し、「別ページに偶然あった一致」と区別する。

### 4.2 自動キーワード一致

正解回答から、助詞・記号・一般語を除いた2文字以上の語を3〜10個選ぶ。表記正規化はUnicode NFC、全半角空白の統一、連続空白の圧縮に限定する。数字、単位、固有名詞は落とさない。

評価単位ごとに次を計算する。

`キーワード一致率 = 出力に含まれた正解キーワード数 / 正解キーワード総数`

完全一致だけではOCRの軽微な揺れを過小評価するため、編集距離による近似一致は補助列に分ける。近似一致を完全一致へ混ぜない。画像typeで正解が図の意味理解を要する場合は、OCR文字列だけの一致を満点根拠にしない。

### 4.3 LLM判定または目視

LLMには質問、正解回答、変換テキストの該当箇所だけを渡し、次の三値をJSONで返させる。

- `sufficient`: 正解回答に必要な根拠が揃う。
- `partial`: 一部はあるが、回答を確定できない。
- `missing`: 根拠がない、または誤っている。

LLM名、版、温度、プロンプトを保存する。LLMを使わない場合は、各プロダクトから段落・表・画像typeを最低2件ずつ目視する。自動一致とLLM判定が食い違う項目は必ず目視する。

### 4.4 表・文字品質

表は次を0〜2点で採点する。0は欠落、1は内容を追えるが構造が崩れる、2は行・列・見出し・結合セルの意味を保つ。セル値の正しさ、列ずれ、複数ページ表の見出し継承、脚注の混入を確認する。

文字品質では、文字化け、脱字、重複、読み順、縦書き、禁則、数字・小数点・負号・単位、ヘッダーとフッターの混入を確認する。図は代替文、キャプション、本文からの参照関係を確認する。

## 6. 全件へ進む判断基準

次をすべて満たすプロダクトを、原則として用途別上位2製品まで選ぶ。

1. キーワード完全一致率が用途別上位2位以内、または最高値との差が3ポイント以内である。
2. 表typeを対象とする場合、表再現性平均が1.5以上である。
3. 成功率が90%以上で、暗号化PDF以外の再現性あるクラッシュ、幻覚、ページ丸ごとの欠落がない。
4. L4 24 GBとRAM 16 GBに収まり、1文書ずつの実行でOOMにならない。
5. 想定用途がライセンス条件を満たす。

総合点だけで用途差を隠さない。文字埋込み用とスキャン用で別製品を選んでよい。速度は精度条件を満たした製品間の順位決定に使う。

## 7. 第2段階: 全件実行

選定したプロダクトだけで次を実行する。`${product}` は実際の識別子へ置き換える。

```bash
product=docling
python3 "scripts/convert_${product//-/_}.py" --all
python3 scripts/aggregate_metrics.py
```

中断後は同じコマンドを再実行する。変換済みファイルをスキップするため、スポットインスタンス中断後も未完了分から続行する。全件結果では、サンプル結果と指標定義を変えない。
