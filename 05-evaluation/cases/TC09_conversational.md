# TC09: 会話文脈依存 — ケース手順書

| 項目 | 内容 |
|---|---|
| 観点 ID | TC09 |
| 観点 | 「その例外は?」のような直前の会話を前提とする質問で、文脈を解決して検索・回答できるか |
| 主な検証対象 | クエリ書き換え(history-aware retrieval)。会話 UI 特有の失敗の主因 |
| 使用ケース | `TC09-*`(サンプル: TC09-001「その例外はありますか」← 解雇予告の会話の続き) |

## 1. 目的

単発の質問では起きない、**会話ならではの検索失敗**を検出する。「その」「それ」「3 番目の」等の指示語だけの質問は、そのままベクトル検索しても意味を持たないため、履歴を使った質問の書き換え(または履歴の連結)が機能しているかを検証する。

検出したい失敗モード:
- 指示語だけで検索して無関係チャンクがヒットし、文脈と無関係な回答をする
- 直前の話題ではなく、より前の話題に誤って解決する

## 2. 前提条件

- [ ] 評価用コーパスの取り込みが完了
- [ ] `TC09-*` ケースに `history` フィールド(直前のやりとり)が登録されている
- [ ] 検証対象の構成が会話履歴をどう扱うか把握している(下表)

| 構成 | 履歴の扱い(現状の実装) |
|---|---|
| 案1(Chainlit) | 履歴なし(単発)。**本観点は対象外**(検証するなら履歴連結の実装追加が先) |
| 案1b(Open WebUI 内蔵 RAG) | Open WebUI 内蔵 SQLite に会話履歴を保持し、会話画面で参照できる |
| 案2(rag-api) | Open WebUI から全履歴が渡るが、検索には**最後の user メッセージのみ**使用(`main.py`) |
| 案3(rag-api) | 同上 + LangGraph のクエリ書き換えは「空振り時の言い換え」のみで履歴は未使用 |

> つまり現行実装は TC09 が**弱い設計**であり、本観点はその改善(履歴を踏まえた質問の書き換え)の効果測定に使う。

## 3. データ準備

- `history` に 1〜2 往復の直前のやりとりを入れ、`question` は指示語を含む続きの質問にする
- ground_truth は「文脈が正しく解決された場合」の答えを書く
- バリエーション: 指示語(「その」)/ 省略(「例外は?」)/ 番号参照(「3 つ目の手順は?」)/ 話題転換後の再参照

## 4. 実行手順

### 4.1 自動評価

```bash
cd test/level2 && python run_level2.py
# run_level2.py は history を質問に前置する簡易書き換えで検索する(サンプル実装)
# TC09 カテゴリの生成品質を確認する
```

> レベル1 スクリプトは単発質問前提のため TC09 の検索評価には `run_level2.py` 側を使う。

### 4.2 手動確認(TC09-001 の例 — こちらが本命)

WebUI(Open WebUI)で**実際の会話として**実行する:

1. 「労働基準法の解雇予告について教えてください。」と入力し、30 日前予告(第 20 条)の回答を得る
2. 続けて「**その例外はありますか。**」とだけ入力する
3. 回答が「天災事変等で事業継続不可能な場合」「労働者の責に帰すべき事由(行政官庁の認定)」(第 20 条ただし書)を指していることを確認する
4. **誤解決テスト**: 新しいチャットで、先に「個人情報の定義」を聞いてから解雇予告 → 「その例外は?」と続け、直前の話題(解雇予告)に解決されることを確認する

## 5. 期待結果と判定基準

| # | 確認項目 | 期待結果 | 判定 |
|---|---|---|---|
| 1 | 文脈解決 | 「その」が直前の話題(解雇予告)に解決される | 合/否 |
| 2 | 検索の的中 | 第 20 条ただし書のチャンクが参考資料に含まれる | 合/否 |
| 3 | 無文脈回答の回避 | 「何の例外ですか?」と聞き返す、または文脈で答える(無関係な回答をしない) | 合/否 |
| 4 | 複数話題の切り分け | 誤解決テストで古い話題に引きずられない | 合/否 |

判定の補足: 聞き返し(確認)は**合格**とする。危険なのは無関係チャンクに基づく断定回答。

## 6. 不合格時の切り分け

1. rag-api のログで検索に使われたクエリ文字列を確認する(指示語のままなら書き換えが未実装/未動作)
2. 改善の定石: 検索前に LLM で「履歴 + 最新質問 → 独立した質問」への書き換えを追加する(rag-api の `chat_completions` で `req.messages` の履歴を使う。[rag-components.md §5](../../docs/rag-components.md) の history-aware retriever)
3. 書き換え後も外す場合は、書き換えプロンプトに「直近の話題を優先」と明示する
