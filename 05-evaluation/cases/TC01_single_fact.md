# TC01: 単純事実(single-hop)— ケース手順書

| 項目 | 内容 |
|---|---|
| 観点 ID | TC01 |
| 観点 | 単一の文書箇所に答えがある基本の質問に、正しく検索・回答できるか |
| 主な検証対象 | 検索・生成の基本動作(このカテゴリが低いと他観点の議論は無意味) |
| 使用ケース | `TC01-*`(サンプル: TC01-001「個人情報保護法でいう『個人情報』の定義」) |

## 1. 目的

RAG の最も基本的な動作を確認する。**TC01 は全観点のベースライン**であり、ここが目標未達の場合は他観点の改善に着手せず、まず基本の検索品質(チャンク分割・Embedding)を修正する。

検出したい失敗モード:
- 定義・数値・日付など、文書に明記された事実を検索できない(チャンク分割で定義文が分断されている等)
- 検索は当たっているのに回答が根拠と食い違う(生成が文脈を無視)

## 2. 前提条件

- [ ] 評価用コーパス(サンプルは e-Gov 法令: 個人情報保護法・労働基準法)の取り込みが完了
- [ ] `TC01-*` ケースが 5 件以上登録されている(サンプルは 1 件のみなので実運用では追加する)

## 3. データ準備

- 質問の作り方: 「X の定義は?」「X は何条?」「X はいつ?」のように、**答えが 1 チャンクに収まる**質問にする。複数文書にまたがる場合は TC02 に分類する
- evidence: 答えを含む条文・段落の中から、**チャンク分割位置に依存しない短い一節**を quote に指定する(例: `生存する個人に関する情報であって`)

## 4. 実行手順

### 4.1 自動評価

```bash
cd 05-evaluation/level1 && python run_level1.py
# 「カテゴリ別 HitRate@4」の TC01_single_fact 行を確認
```

### 4.2 個別ケースの手動確認(TC01-001 の例)

```bash
python run_level1.py --case TC01-001 --verbose
```

1. 出力で `HIT` 付きチャンク(第2条第1項の定義文)が**1〜2 位**に入っていることを確認する
2. WebUI を開き、「個人情報保護法でいう「個人情報」の定義を教えてください。」と入力する
3. 回答に「生存する個人に関する情報」「特定の個人を識別できる」の要素が含まれ、参考資料に法令ファイル名が表示されることを確認する

## 5. 期待結果と判定基準

| # | 確認項目 | 期待結果 | 判定 |
|---|---|---|---|
| 1 | 検索順位 | 正解根拠チャンクが Rerank 後 5 件中 1〜2 位 | 合/否 |
| 2 | 回答の事実一致 | ground_truth の必須要素(定義の骨子)を含み、矛盾がない | 合/否 |
| 3 | 余計な創作がない | コンテキストにない条文番号・要件を付け足していない | 合/否 |
| 4 | 出典表示 | 参考資料に根拠文書名が含まれる | 合/否 |

カテゴリ目標: HitRate@4 = 1.0 に近いこと(TC01 は最も易しい観点。0.9 を切るなら基盤に問題)

## 6. 不合格時の切り分け

1. `--verbose` で正解根拠が**候補 20 件にも入っていない** → チャンク分割で定義文が分断されていないか(`CHUNK_SIZE` と分割位置を確認)、e5 系のプレフィックス付け忘れがないかを確認
2. 候補には入るが上位に来ない → Reranker のモデル・しきい値を確認
3. 検索は当たるが回答が誤る → プロンプトのコンテキスト件数を減らす(上位 3 件)、`answers.jsonl` で LLM に渡った実際のコンテキストを確認
