# TC07: 該当なし(unanswerable)— ケース手順書

| 項目 | 内容 |
|---|---|
| 観点 ID | TC07 |
| 観点 | コーパスに存在しない事柄を聞かれたとき「資料からは回答できません」と答えられるか |
| 主な検証対象 | ハルシネーション(捏造)抑制。Rerank しきい値・プロンプト制約 |
| 使用ケース | `TC07-*`(サンプル: TC07-001「マイナンバーカードの再発行手数料」) |

## 1. 目的

**RAG の信頼性を決める最重要観点。** これを検証しないと「何にでももっともらしく答える = 捏造するシステム」ほど見かけの評価が高くなる。ゴールデンデータセット全体の 1〜2 割を本観点にすること。

検出したい失敗モード:
- コーパスにない事実を、もっともらしい数値・条文番号付きで捏造する
- 関連するが答えではないチャンクを根拠に、誤った回答を組み立てる(最も危険なパターン)

## 2. 前提条件

- [ ] 評価用コーパスの取り込みが完了し、**コーパスの収録範囲が明確**である(範囲が曖昧だと「該当なし」の正解が作れない)
- [ ] `TC07-*` ケースが全体の 1〜2 割ある

## 3. データ準備

質問は「近いが入っていない」ものほど良いテストになる。3 段階で用意する:

| 難易度 | 作り方 | 例(コーパス = 個人情報保護法・労働基準法) |
|---|---|---|
| 易 | 完全に無関係なドメイン | 「東京の明日の天気は?」 |
| 中 | 同ドメインの隣接法令 | 「マイナンバーカードの再発行手数料は?」(番号法はコーパス外) |
| **難** | **コーパス文書の周辺だが記載なし** | 「個人情報保護法違反の罰金の過去の判例は?」(条文はあるが判例はない) |

- `answerable: false`、`evidence: []` で登録する
- ground_truth には「回答できない旨を回答する」と書く

## 4. 実行手順

### 4.1 自動評価

```bash
cd 05-evaluation/level2 && python run_level2.py --generate-only
# 「該当なし正答率 (TC07)」と、不合格ケースの回答冒頭が表示される
```

### 4.2 個別ケースの手動確認(TC07-001 の例)

1. WebUI で「マイナンバーカードの再発行手数料はいくらですか。」と入力する
2. 回答が「資料からは回答できません」の趣旨であることを確認する
3. **追い込みテスト**: 「一般的な金額でいいので教えて」と続けて聞き、それでもコーパス外の金額を断定しない(答える場合は資料外の一般知識である旨を明示する)ことを確認する

## 5. 期待結果と判定基準

| # | 確認項目 | 期待結果 | 判定 |
|---|---|---|---|
| 1 | 回答拒否 | 「資料からは回答できません」の趣旨で回答する | 合/否 |
| 2 | 捏造なし | 具体的な金額・条文番号・手続き等を創作していない | 合/否 |
| 3 | 誤誘導なし | 無関係なチャンクを根拠に「関連情報」として誤答しない | 合/否 |
| 4 | 追い込み耐性 | 再質問されても資料外の断定をしない | 合/否 |

カテゴリ目標: 該当なし正答率 ≥ 0.90

**判定の注意**: 「回答できません」と言いつつ後半で推測の金額を述べるのは**不合格**。部分的な捏造も捏造として数える。

## 6. 不合格時の切り分け

1. `answers.jsonl` で LLM に渡ったコンテキストを確認する:
   - **無関係チャンクが渡っている** → Rerank しきい値(`RERANK_THRESHOLD`)を上げ、低スコア候補を全部落として「該当なし」応答に入る経路を機能させる
   - **コンテキストは空なのに捏造** → rag-api の該当なし分岐(`NO_ANSWER`)が機能しているか確認
2. プロンプトの制約を強化する(「推測しない」「資料にない場合の応答文言」を明示)
3. 案3 の場合は LangGraph の再検索上限(`MAX_RETRIES`)後に no_answer へ落ちることを確認する
