1. まず押さえる全体像

初動 TTFT 送信直前 → 最初の非空コンテンツ
生成間隔 TPOT (ITL) 最初のコンテンツ後の平均時間
実効生成速度 tokens/s チャンク数 ÷ エンドツーエンド時間
全体 総応答時間 送信直前 → data: [DONE]

Locustはリクエスト直前に高精度タイマーを開始し、stream: true で POST /api/chat/completions を送ります。レスポンスを response.iter_lines() で逐次読みし、choices[0].delta.content が非空のSSE行だけをコンテンツチャンクとして数えます。

解析不能なSSE行、空行、delta.content のない終了チャンクは指標計算から除外し、data: [DONE] で読み取りを終了します。

Open WebUIがメタデータや引用情報を先に送っても、非空の choices[0].delta.content でなければTTFTは確定しません。

3. 各指標の計算方法

TTFT — Time To First Token

TTFT = first_content_at - started Locustへの登録時に秒からミリ秒へ変換します。

送信直前から、最初の非空コンテンツチャンクを受け取るまでの時間です。nginx、Open WebUI、RAG検索・リランク、vLLMの待ち時間とプリフィル、ネットワーク往復を含むクライアント層のTTFTです。

TPOT (ITL) — Time Per Output Token

TPOT = (total_seconds - ttft_seconds) / max(chunk_count - 1, 1) 1リクエストにつき「最初のコンテンツ後の平均チャンク時間」を1件記録します。

各チャンク間隔を個別に記録する実装ではありません。各リクエストの平均TPOTを算出し、そのリクエスト間分布についてLocustがp50・p95などを集計します。

Output token throughput — tokens/s

tokens_per_s = chunk_count / total_seconds 実トークン数ではなく、非空コンテンツチャンク数をトークン数として近似します。

現在の式はTTFTを含む総所要時間で割るため、vLLMデコード区間だけの速度ではなく、ユーザー視点のエンドツーエンド実効スループットです。

計算例

総所要時間 5.0秒、TTFT 2.0秒、コンテンツチャンク数31

TPOT = (5.0 − 2.0) ÷ (31 − 1) = 0.1秒 = 100ms

tokens/s = 31 ÷ 5.0 = 6.2 tokens/s（近似）

Locustの response_time 欄を流用しているため同じ時間列に表示されますが、SSE tokens_per_s の値だけはmsではなくtokens/sです。また、派生イベントもリクエストとして集計されるため、Aggregatedの件数・req/sは実チャット数の約4倍になります。Request throughputには POST /api/chat/completions 行のreq/sを使います。

5. 案1bでもTTFTは取得できるか

取得できます。 案1bには専用rag-apiがありませんが、Open WebUI自身が内蔵RAGを実行し、vLLMの生成結果をSSEでLocustへ中継します。

6. 数値を解釈するときの注意

  • 1チャンク = 1実トークンではありません。 vLLMやOpen WebUIが複数トークンをまとめたり、1トークンを分割したりすると実トークン数との差が生じます。
  • 案2・案3の参考資料footerも1チャンクに数えます。 生成本文の実トークン数に対して、おおむね+1チャンクの誤差になります。
  • 案1bは中継実装の影響を受けます。 Open WebUIがSSEチャンクを結合・分割すると、TTFTと総応答時間は比較しやすい一方、TPOT・tokens/sのチャンク近似誤差が変化します。
  • 現在のTPOTには末尾処理も含まれます。 最初のコンテンツから [DONE] までを使うため、footer、stop、通信上の終端処理の時間が含まれます。
  • 比較条件を固定します。 同じ質問、モデル、生成長、コーパス、同時ユーザー数で案1b・案2・案3を比較します。

7. 失敗判定と派生指標

次のいずれかに該当する場合、本体の POST /api/chat/completions をfailureとして扱います。

  • HTTPステータスが400以上
  • data: [DONE] を受信できない
  • 非空のコンテンツチャンクが1つもない
  • 全コンテンツを連結した結果が空白だけになる

失敗時には ttft、tpot、tokens_per_s の派生イベントを発火しません。このため、派生指標の件数は成功した本体リクエスト数と一致します。

HTTP / SSE validation
        │
        ├─ failure ──→ POSTを失敗として記録、派生指標なし
        │
        └─ success ──→ POST総時間 + SSE ttft + SSE tpot + SSE tokens_per_s
