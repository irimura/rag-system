# Claude Code 向けレビュー検証プロンプト

以下を Claude Code の新しいセッションで、そのまま依頼文として使用する。

```text
このリポジトリは Codex による一次レビューを受けています。
このターンでは一次レビューの妥当性検証だけを行ってください。資料本体やサンプル実装の修正には進まないでください。

最初に AGENTS.md と agent/session.md を全文読み、確定済みの設計判断と執筆・Git 規約を把握してください。その後 agent/review.md を全文読んでください。

作業内容:

1. 作業前に git status を確認してください。既存の未コミット変更は上書き・巻き戻ししないでください。
2. agent/review.md の R-01〜R-10 を、リポジトリの実装・ドキュメントと公式一次情報から独立に検証してください。Codex の結論を前提にせず、誤りがあれば明確に否定・訂正してください。
3. 各指摘を「確認済み」「一部確認」「誤り」「未確認」のいずれかに分類し、検証後の重要度、根拠ファイルと行番号、公式 URL、訂正内容を記録してください。
4. 外部仕様・ライセンス・現行バージョン・AWS の挙動は、ブログや検索結果の要約ではなく、ベンダー公式ドキュメント・公式リポジトリ・公式ライセンスを優先してください。確認できなければ推測せず「未確認」としてください。
5. 静的確認だけで断定できない実行時挙動は、利用可能な既存ツールで安全に検証してください。ただし AWS リソースの作成、外部サービスの変更、資料修正、依存関係の恒久インストールは行わないでください。実行できなければ未確認として、必要な将来の検証方法を記載してください。
6. agent/review.md を検証済みの内容に上書きしてください。ただし、R-01〜R-10 の ID と一次レビューの主張要約は監査用に残し、判定変更履歴、検証日、検証者、検証時コミット ID、実行コマンドを記録してください。
7. agent/session.md を更新してください。検証で確認できた重要事項、誤りだった指摘、未確認事項、次フェーズが Codex による資料修正であることを、既存の確定設計を覆さない形で追記してください。未検証の主張を確定事項として書かないでください。
8. AGENTS.md、README.md、docs/、deploy/、test/、eval/ は変更しないでください。
9. 最後に git diff --check、git diff -- agent/review.md agent/session.md、git status --short --branch を確認してください。
10. コミットは作成せず、検証結果の要約と変更ファイルを報告して停止してください。

重要なフェーズ境界:
- 今回はレビュー検証と引き継ぎ更新までです。
- 指摘が正しくても、修正は実装しないでください。
- 設計判断を変更する必要がある場合は、agent/review.md に「ユーザー判断が必要」と記録し、独断で変更しないでください。
```

## 推奨する後続フロー

1. Claude Code が `agent/review.md` を検証済み内容へ更新し、`agent/session.md` に引き継ぐ。
2. ユーザーが検証結果を確認する。ライセンス要件など設計判断が必要な項目だけ先に決める。
3. Codex が `agent/session.md` と検証済み `agent/review.md` を読み、確認済み指摘だけを修正する。
4. 修正は論理単位で分け、評価コード、デプロイ、AWS 手順、文書整合性を一度に混ぜない。
5. 修正後に、可能なら Claude Code または別セッションで回帰レビューを行う。

一次レビューを履歴ごと消して単純に置換するより、指摘 ID と判定変更履歴を残す方が、Codex と Claude Code の見解差を追跡できるため安全である。
